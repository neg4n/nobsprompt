## Requirements

- macOS 13 or newer, on Apple Silicon or Intel;
- Zsh 5.8 or newer;
- Zig exactly 0.16.0;
- Git 2.25 or newer.

Zig's build system compiles and installs the native application without Make,
Meson, Ninja, Python, or third-party Zig packages. The default is ReleaseSafe,
with runtime checks and a baseline CPU target. Zig remains pre-1.0: future
compiler versions are not assumed compatible with this pinned release.

Expect is optional for building and installing. With the default
`zsh_tests=auto` setting, the Zig build does not register the four PTY-backed
interactive Zsh tests when Expect is unavailable; `-Dzsh_tests=enabled` makes
Expect required.

## Build and install

<Steps>
  <Step title="Clone source, tests, benchmark, and local docs">

  ```sh
  git clone --branch codex/zig-rewrite --depth 1 --filter=blob:none --sparse --no-tags https://github.com/neg4n/nobsprompt.git && cd nobsprompt && git sparse-checkout set src tests bench doc docs verification
  ```

  :::tip
  This gets the native source, tests, benchmark harness, and local docs without
  downloading the website project or videos. To get everything instead:

  ```sh
  git clone --branch codex/zig-rewrite https://github.com/neg4n/nobsprompt.git && cd nobsprompt
  ```
  :::

  </Step>
  <Step title="Review the exact source you will build">

  AI-assisted review can improve visibility, but it cannot prove that software
  is safe. Review the exact checked-out commit and resolve any uncertainty
  before running build or installation commands.

  <Prompt
    description="Copy a focused **pre-build source audit** for your coding agent."
    actions={["copy"]}
  >
    Treat this checkout as untrusted. Do not build, install, or execute
    repository code during the review. Record the current commit hash. Trace
    the complete `zig build install` control flow through build.zig,
    build.zig.zon, Zig sources, and embedded Zsh. Inventory every
    executable, script, dependency, subprocess, and generated input reached by
    that flow. Inspect for unexpected URLs or network access, shell execution,
    process spawning, filesystem writes or deletion outside the documented
    prefix and cache, persistence, privilege escalation, credential or
    sensitive environment access, dynamic loading, obfuscated or encoded
    payloads, cryptocurrency mining behavior, telemetry, and unexplained
    background work. Check tracked symlinks, submodules, binary blobs, and
    whether any excluded directory is referenced by the build. Report findings
    with file and line evidence, distinguish expected behavior from suspicious
    behavior, list unresolved uncertainties, and state whether the reviewed
    source is reasonably consistent with the documented behavior. Do not claim
    proof of safety.
  </Prompt>

  </Step>
  <Step title="Install the executable and documentation">

  ```sh
  zig build install --prefix "$HOME/.local"
  ```

  This explicitly selects `~/.local`. Plain `zig build` installs into
  `zig-out` for local development. Use `--prefix` for another destination or
  `DESTDIR` for a staged installation.

  </Step>
  <Step title="Put nbsp on PATH">

  ```zsh
  export PATH="$HOME/.local/bin:$PATH"
  ```

  Add this before the `nbsp` initialization line in `~/.zshrc` so the shell can
  run `nbsp init` (unless you invoke the binary by absolute path). Omit it when
  `~/.local/bin` is already on `PATH`.

  `init` embeds `_NBSP_BIN` as the absolute path of that binary so data and
  refresh hooks keep working if `PATH` is rearranged later. After moving or
  upgrading the install location, re-run `eval "$(nbsp init zsh …)"`.

  </Step>
  <Step title="Choose one integration">

  <Tabs param="mode">
    <Tab title="Opinionated prompt">

    ```zsh
    eval "$(nbsp init zsh --autosuggest)"
    ```

    </Tab>
    <Tab title="Detached mode">

    ```zsh
    eval "$(nbsp init zsh --detached --autosuggest)"
    ```

    </Tab>
  </Tabs>

  These recommended commands enable recent-history ghost text and bounded,
  path-aware `cd` suggestions.

  :::warning[Use one autosuggestion engine]
  Do not combine nobsprompt autosuggestions with `zsh-autosuggestions` or
  another plugin that owns ghost text. If one is already installed, omit
  `--autosuggest` and use `eval "$(nbsp init zsh)"` or
  `eval "$(nbsp init zsh --detached)"`. Nobsprompt detects common conflicts,
  disables only its autosuggestion engine, and leaves the prompt working.
  :::

  `NVM_BIN` is read on every prompt or data collection, so NVM initialization
  order does not determine Node-version detection. The first prompt mode
  initialized in a shell still wins.

  </Step>
  <Step title="Restart Zsh">

  ```zsh
  exec zsh
  ```

  Opening a new terminal has the same effect.

  </Step>
</Steps>

## Installed files

With the default prefix, installation places:

| File | Location |
| --- | --- |
| Executable | `~/.local/bin/nbsp` |
| Man page | `~/.local/share/man/man1/nbsp.1` |
| MDX source documentation | `~/.local/share/doc/nobsprompt` |

Use `man nbsp` for the terminal reference.
